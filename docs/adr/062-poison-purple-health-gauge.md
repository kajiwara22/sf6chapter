# ADR-062: A.K.I. の毒状態で紫になる体力ゲージを現在体力として計測

## ステータス

採用 - 2026-10-13（実装完了 2026-10-13）

## 文脈

### 問題: A.K.I. の毒で体力バーが紫になると health が崩落する

ADR-061 で低体力時の明るい黄色を現在体力に含めたが、**A.K.I. の毒状態では現在体力バーが紫に変わる**。この紫（実測 H≈139, S≈140, V≈171〜176）は `health_hue_ranges`（1P マゼンタ〜赤 / 2P 青）にも `health_low_hue_ranges`（黄 15〜50, ADR-061）にも該当せず、毒状態の間 `health` が 0 近くまで崩落していた。

実測（`rNhYCktBpPM` / `_353` R1、P1=JP が A.K.I. の毒を受ける）:

| 動画時刻 | P1 のバー色 | 変更前の `health` |
|---------|------------|------------------|
| t=369.0 | ピンク (H≈169) | 93.0% |
| t=370.0 | **紫 (H≈140)** | **2.8%（崩落）** |
| t=374.0 | ピンク (H≈169) | 58%（復帰） |

毒は P1 / P2 のどちらにも付与され、**紫の色相は両サイド共通**（A.K.I. が P1 の `_2076` R1 では P2 のバーも H≈139）。

### 紫は「現在体力」そのもの

毒中は、紫の帯（現在体力）の外側にオリーブ〜暗黄の帯（回復可能／毒の残量表示）が現れる。紫の帯長は前後のピンクの帯長と連続しており（`_353` R1: ピンク 92% → 紫 84% → ピンク 58%）、**紫は現在体力**として扱ってよい。

| 動画時刻 | 紫（現在体力） | オリーブ（回復可能側） |
|---------|--------------|----------------------|
| t=370.0 | 104〜677（574列, 83%） | 4〜91（77列） |
| t=373.5 | 268〜677（410列, 59%） | 104〜257（154列） |
| t=374.0 | ピンク 281〜679（399列, 58%） | 101〜275（175列） |

### 毒の紫は画面演出の紫と色相が重なる

毒の紫（H≈139）は、スーパーアーツ／K.O. 演出などの画面全体を覆う紫のエフェクトとも色相が重なる。実際に A.K.I. を含まない試合でも、ラウンド終盤の演出中に体力 ROI の一部が紫になり、現在体力として誤検出されることを確認した（後述の検証結果）。

そのため、**毒の紫の採用は A.K.I. を含む試合に限定する**。

## 決定

### 1. 毒の紫を現在体力に含める色域を追加する

- `health_poison_hue_ranges`（既定: 両サイド `[[130, 150]]`）を追加する
- `_current_health_mask()` に「毒の紫」を OR で加える

### 2. 採用は A.K.I. を含む試合に限定する

- `feed()` では毒なし（`health_raw`）と毒込み（`health_poison_raw`）の 2 系列を計測し、`_derive_states()` で両方を平滑化する
- `build()` は試合ごとの `characters` から A.K.I. の有無を判定し、A.K.I. を含む試合だけ毒込み系列を採用する
- これにより、非 A.K.I. 試合では紫を一切現在体力に含めない（誤検出を回避）

### 3. 明度・彩度は通常の現在体力と同じ閾値を使う

毒の紫は明度分離を必要としない（体力バー上に競合する同系色がない）ため、`health_filled_v` / `health_filled_s` をそのまま使う。

### 4. `healthRecoverable` は変更しない

ADR-054 / ADR-058 の系列は変更しない（紫は `health_recoverable_hue_ranges` の黄 15〜50 に該当しないため、そもそも混入しない）。

## 検討した選択肢

| 選択肢 | 概要 | 結論 |
|--------|------|------|
| A. 毒の紫を常時現在体力に含める | 全試合で `health_poison_hue_ranges` を適用 | 不採用 |
| B. 毒の紫を A.K.I. 試合に限定して含める | `characters` で判定し、試合ごとに系列を選ぶ | **採用** |
| C. `health_hue_ranges` 自体を紫まで拡張 | 1P を `[130,179]` にする等 | 不採用 |
| D. 毒を別系列として計測 | `healthPoison` を Web に追加 | 不採用 |

### A を採用しなかった理由

- A.K.I. を含まない試合でも、K.O.／SA 演出の紫を体力として誤検出する（実測: `Ndwu08Q--_M_480` R2 P1 のラウンド終端で 6.2% → 20.6%）
- 色相を狭めても（`[135,145]` / `[136,144]`）誤検出は消えない

### B を採用した理由

- `build()` はもともと試合ごとの `characters` を受け取っており、追加の配線が最小で済む
- 非 A.K.I. 試合の結果を ADR-061 と完全に一致させられる

### C を不採用にした理由

- 「通常の現在体力」と「毒の現在体力」の区別が設定から消え、将来の特殊表示色を追加する余地がなくなる

### D を不採用にした理由

- 毒でもユーザーが見たいのは「現在体力」そのものであり、別系列にするとグラフが 0 のままになる
- スキーマ・Web・Parquet の変更が必要になり、変更範囲が大きすぎる

## 帰結

- 毒状態でも `health` が実値で記録される（`_353` R1 t=370: 2.8% → 89%）
- 非 A.K.I. 試合の結果は ADR-061 から変わらない（紫を常時適用した場合の KO 演出誤検出を回避）
- 毒の紫は両サイド共通のため、既定は両サイド同値（`[[130, 150]]`）
- `feed()` で体力計測が 2 回になる（毒なし／毒込み）。コストはテンプレートマッチングに比べて小さく、試料間隔も変わらない
- 今後、別キャラの特殊表示色が出た場合は同じ枠組み（試合キャラでゲート）で追加する

### 非 A.K.I. 試合への影響なし

`rNhYCktBpPM` 内の非 A.K.I. 試合（15 試合）は、毒を常時適用した場合にはラウンド終端の演出紫で health がずれた（例: `_480` R2 P1 の終端 6.2% → 20.6%）が、ゲート導入後は **ADR-061 の結果と完全に一致**（差分 0 件）。

### 再処理スクリプトの修正

`scripts/reprocess_gauge.py` は `analyzer.build()` に `characters` を渡しておらず、ADR-054（エレナの SA2）と ADR-062（A.K.I. の毒）のゲートが効かなかった。本線パイプライン（`main.py`）と同じ形で `characters` を渡すよう修正した。

### R2 反映

`rNhYCktBpPM` を再計測後、`scripts/upload_gauge_data.py` で R2（`gauges/{matchId}.json` / `round_stats.parquet` / `manifest.json`）を更新済み（round_stats 100 行、manifest version `b317067464e8e200`）。
