# ADR-068: パーフェクト勝利ラウンドの残体力・ラウンド長補正

## ステータス

採用 - 2026-10-28

## 文脈

`NdfHMgNzGFU_4070` のラウンド3（CAMMY が JP にパーフェクト勝利、動画 4176.75〜）で、
勝者 CAMMY の残体力が **3.9%（390 / 10000）** と記録された。実際は無傷の 100% である。

### 原因

1. **K.O. バナーが未検出**
   パーフェクト勝利時は「PERFECT」の白文字が K.O. と同時に表示される（動画 4200.8 秒〜）。
   白/銀マスク照合（ADR-063）は K.O. の位置がずれ、実測 IoU は 0.48 だった。
   ADR-067 で誤検出との分離に使っている閾値 0.65（および誤検出の実測上限 0.645）より低いため、
   K.O. として確定しない。

2. **`visible_to` が勝利演出まで伸びる**
   ADR-059 の「K.O. 以降の可視を打ち切る」処理は `ko_time` に依存する。K.O. が無いため、
   HUD が消える 4204.85 秒までがラウンド終端になった（実 K.O. は 4200.5 秒ごろ。
   `durationSec` も 27.5 秒と、勝利演出 4〜5 秒を含んでいた）。

3. **HUD 消失後の背景を現在体力色として誤読**
   HUD が消えた直後の 2 サンプル（4204.75 秒 = 52.0%、4204.85 秒 = 3.9%）は、桜の花びら（ピンク）を
   1P の現在体力色（H 145–179 / 0–15）として拾ったもの。これが health 系列の最終値なので、
   下振れ補正（ADR-054）でも戻せない。

### 影響範囲

手元の `intermediate/*/gauges/round_stats_preview.json` を横断すると、パーフェクト勝利は 29 ラウンド。
**29 ラウンドすべてで K.O. が未検出**、うち **28 ラウンドで勝者の `healthEnd` が 100% 未満**
（100.0 は 1 件のみ）。例:

| matchId | round | healthEnd | durationSec |
|---|---|---|---|
| `NdfHMgNzGFU_4070` | 3 | 3.9 | 27.5 |
| `NdfHMgNzGFU_1044` | 1 | 1.0 | 28.0 |
| `M-W3Eqm6bvs_824` | 1 | 1.2 | — |
| `rf-kzjE9mTk_1991` | 3 | 5.3 | 32.6 |

## 検討した代替案

| 案 | 実測 | 判定 |
|---|---|---|
| K.O. 白マスクの位置探索型 IoU（`TM_CCORR` で最良位置を探索） | PERFECT 併記の K.O. は IoU 0.482（同一座標 0.377 から改善するが閾値未満） | 不採用 |
| テンプレートの複数スケール探索（0.4〜1.0） | 最良でも IoU 0.482。テンプレート自体が背景の白を含み、ステージ依存 | 不採用 |
| PERFECT バナー用テンプレートの追加 | PERFECT 文字は固定デザインで有望だが、検証環境で 1080p フレームを取得できず閾値の根拠を作れない | 将来課題 |
| 敗者の体力 0% 到達を全ラウンドの K.O. 指標にする | `rf-kzjE9mTk_880` で HUD の一時消失（0.3 秒）を K.O. と誤認し、`durationSec` が 28.7 → 17.9 秒に破壊（ADR-067 の再発） | 不採用（パーフェクト限定なら安全） |

パーフェクトの敗者はラウンド中に一度もダメージを受けないため、体力が 5% 以下になるのは
K.O. の瞬間だけである。この性質を使えば、Battlelog の `round_results`（`P`）と組み合わせて
誤検出を避けられる。

## 決定

### 1. パーフェクト勝利の勝者は残体力 100%

`build_round_stats_rows` で `roundMethod == "P"` かつ `roundResult == "win"` の行は
`healthEnd = 100.0` に補正する。ADR-051 の「K.O. 敗者は 0%」補正と対称。

### 2. パーフェクトラウンドの終端を K.O. 推定時刻で切り詰める

同じく `roundMethod == "P"` のラウンドで、敗者の health 変化点が **5% 以下**になった最初の
相対時刻を K.O. とみなし、`durationSec` / `roundEndTime` を切り詰める。
パーフェクトでないラウンドには適用しない（削り合いを K.O. と誤認しないため）。

パラメータは `PERFECT_KO_HEALTH_PERCENT = 5.0`（`src/detection/gauge.py` の定数）。
ラウンド抽出（`GaugeAnalyzer.build`）の K.O. 判定は変更しない。`gauges.json` の生系列は
実測のまま残す（計測と補正を分離する）。

### 3. 適用結果

- パーフェクト勝利 29 ラウンドのうち 28 ラウンドで `healthEnd` が 100% になる
- `durationSec` は勝利演出を除いた実時間に近づく（例: `NdfHMgNzGFU_4070` R3 は 27.5 → 22.2 秒、
  実 K.O. は開始 +23.6 秒）

## 影響

- Web のラウンド集計（残体力）とゲージ詳細のラウンド長が正しくなる
- `gauges.json` の health 系列には K.O. 後の誤読（100% → 3.9%）が残る。詳細パネルの
  体力グラフには終端の落ち込みが見える。系列自体の補正は別途（HUD 消失直前の急落ガード）

## 残課題

1. **PERFECT バナーのテンプレート検出**: K.O. 時刻そのものを検出できれば、パーフェクト以外の
   ラウンドも含めて `durationSec` と health 終端が正しくなる。1080p フレームでテンプレートを作り、
   誤検出との分離を実測する
2. **health 系列の終端ガード**: HUD が消える直前の急落（直前値の 50% 未満）を捨てる。
   敗者側は ADR-051 の 0% 補正があるため、勝者側だけに効かせられる
3. **ADR-067 の白マスク閾値の再評価**: 位置探索型にすると誤検出（実測 IoU 0.60〜0.65）との
   分離幅が変わるため、閾値の再測定が必要
