# ADR-077: PERFECT 演出の拡大 K.O. 文字を検出する専用テンプレートの追加

## ステータス

採用 - 2026-11-08（実装完了 2026-11-08）

## 文脈

### 問題: パーフェクト勝利のラウンドで K.O. が検出されない

ADR-063 の白/銀マスク照合は、K.O. 文字の形を背景非依存で照合する。
しかしパーフェクト勝利の演出では **K.O. 文字が画面中央に超拡大表示** され、
既存の K.O. テンプレート（通常サイズ）と形が一致しない。

実測（`lHLbZGQ8z1E`、46 ラウンド中 3 ラウンドが未検出。いずれも `roundMethod=P`）:

| ラウンド | 既存テンプレートの IoU | 閾値 |
|---|---|---|
| `_624` R1 | 0.42 | 0.65 |
| `_990` R1 | 0.43 | 0.65 |
| `_1331` R2 | 0.42 | 0.65 |

通常 K.O. は IoU 0.66〜0.75 で検出できている。原因の切り分け:

- 白マスクの画素数は 98,827（パーフェクト）対 151,439（通常）で、文字の白が不足している
- 5 テンプレートの白マスクの AND（背景の偶然の白を除去）でも 0.42 のまま
- `s_max` / `v_min` を緩めても 0.47 止まり

つまり背景の混入ではなく、**文字の外形そのものが拡大版で異なる**ことが原因である。
閾値を 0.43 付近まで下げると、ADR-063 で分離した「白い服装＋明るいステージ」の
誤検出（実測 0.60〜0.64）を確実に拾ってしまうため、閾値の引き下げでは解決できない。

なお ADR-068 で、パーフェクト勝利の `durationSec` は敗者の体力が 0% 付近に落ちた時刻で
切り詰めており、`healthEnd` も 100% に補正している。そのため実データへの影響は限定的だが、
`koTimes` の網羅率が落ち、K.O. 後の HUD 途切れに依存する終端推定が甘くなる。

## 決定

PERFECT 演出の拡大 K.O. 文字用テンプレート `template/gauge/ko_banner_perfect.png` を追加し、
`gauge_analysis.ko_banners` に `ko_perfect`（threshold 0.4）として登録する。

- テンプレートは `lHLbZGQ8z1E` の 1013.9 秒（`_990` R1 の PERFECT 演出）から、
  既存テンプレートと同じ検索領域 `[640, 360, 1280, 720]` を切り出して作成した
- 既存の `ko_banners` に追加するだけで、エッジ照合（`_detect_ko_edge`）と
  白/銀マスク照合（`_detect_ko_color`）の両方に反映される
- PERFECT 演出はステージ・キャラクターに依存しない共通 UI のため、1 テンプレートで汎化する

## 検証結果

`lHLbZGQ8z1E` を再計測:

| 指標 | 修正前 | 修正後 |
|---|---|---|
| `koTimes` 件数（46 ラウンド） | 43 | **46** |
| `_990` R1 の K.O. | 未検出 | 1013.5 秒 |
| `_1331` R2 の K.O. | 未検出 | 1406.25 秒 |
| `_624` R1 の K.O. | 未検出 | 655.25 秒 |

新テンプレートのスコア（実フレーム）:

| フレーム | エッジスコア | マスク IoU |
|---|---|---|
| `_990` R1 1013.8 / 1014.0 | 0.950 / 0.946 | 0.999 / 0.998 |
| `_1331` R2 1406.6 | 0.903 | 0.979 |
| 通常 K.O.（66.5 秒） | 0.000 | 0.416 |

誤検出の確認:
- 全編を 3 秒間隔でサンプリングし、新テンプレートのエッジスコアが 0.4 以上になったのは
  検出対象の 1014.0 秒（0.946）のみ
- 通常 K.O. では新テンプレートの IoU が 0.416 と低く、既存テンプレートと役割が分離されている

## 残課題

- K.O. 文字が表示されず暗転する演出は原理的に検出できない。ただしラウンド終端は
  HUD 途切れ（ADR-057）と `boundaryEndTime` で決まり、`healthEnd` は ADR-068 で補正されるため実害はない
