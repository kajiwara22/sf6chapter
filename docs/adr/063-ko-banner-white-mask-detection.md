# ADR-063: K.O.文字の白/銀マスク照合による背景非依存のK.O.検出

## ステータス

採用 - 2026-10-13

## 文脈

### 問題: 背景が変わると K.O. を検出できず、次の試合までの待ち受けが計測される

ADR-057 / ADR-059 は、ラウンド内の HUD 可視範囲（`visibleTo`）を K.O. 検出時刻で打ち切ることで、勝利演出中や次の試合待ちの誤計測を防いでいる。しかし ADR-059 の K.O. 検出は、特定動画（`f36vyEepil4`）から切り出した**エッジテンプレート5枚との相関**で行うため、背景（ステージ）が変わるとスコアが急落する。

実測（`rNhYCktBpPM`、ラウンド終了50件）:

| 方式 | K.O. 検出できたラウンド |
|------|------------------------|
| エッジテンプレート（ADR-059） | **9 / 50 = 18%** |

K.O. が未検出のラウンドでは `ko_time` が得られず `visibleTo` が伸び、待ち受け時間の HUD 誤読がそのまま収集される。具体的には `/matches/rNhYCktBpPM_207` の Round 2（動画264〜318秒）で、K.O. は約314.5秒だが、その後の勝利演出・待ち受け（〜357秒）まで `player1` の health が収集されていた。

各背景ごとにテンプレートを用意する運用は非現実的であるため、**背景に依存しない K.O. 検出手法**が必要だった。

### K.O. 文字は「明るく低彩度な文字の形」

K.O. の文字はどのステージでも同一フォント・同一位置に表示され、内部に背景が透ける半透明の白/銀文字である。エッジ（輝度勾配）は背景のエッジに埋もれるが、**明るく低彩度な画素だけを抜き出した二値マスク**にすれば、背景に関係なく文字の形が共通して現れる。

## 決定

### 1. 白/銀マスクの IoU で K.O. を検出する

- 検索領域: 画面中央 x=640-1280, y=360-720（`base 1920x1080` 基準、既存 K.O. テンプレートと同一）
- マスク条件: HSV で `S < 70` かつ `V > 150`（明るく低彩度な白/銀）
- テンプレート: 既存の K.O. テンプレート画像5枚（ADR-059）を検索領域サイズにリサイズし、同じ条件でマスク化。背景情報を含まない形状のみを使う
- スコア: フレーム側マスクと各テンプレートマスクの **最大 IoU**
- 閾値: `0.6`

### 2. 連続検出で確定し、最初の超過時刻を K.O. 時刻とする

白フラッシュ等の単発ノイズを除外するため、`banner_sample_interval_sec`（0.25秒）間隔で **`min_consecutive = 2` 回連続**して閾値を超えた時点で確定し、**最初に閾値を超えた時刻**を `ko_times` に記録する。連続中に閾値を下回ったらカウンタをリセットする。

### 3. 既存のエッジテンプレート検出と併用する

背景が既知の動画（`f36vyEepil4` 等）ではエッジテンプレートが高精度に機能するため、**どちらかが検出したら K.O. とみなす**。エッジ検出は従来どおり即確定（多重検出は直近3秒で抑制）。

### 4. 検出時刻は既存の打ち切り機構にそのまま流す

`ko_times` → `_round_ko_time()` → `_visible_range()` → `visibleTo` → `roundEndTime` の既存経路は変更しない。K.O. 検出率が上がることで、待ち受け時間の収集が自動的に排除される。

### 5. ゲージ詳細（gauges）のラウンド終了も同じ打ち切りに合わせる

Web のゲージ詳細（`/matches/{matchId}`）は `gauges/{matchId}.json` の各ラウンドの `roundStartTime` / `roundEndTime` を表示区間（グラフの横軸長・ヘッダーの期間）に使う。従来の `roundEndTime` は「次ラウンド開始バナーまで」で、K.O. 後の勝利演出・待ち受けを含んでいた（`round_stats` 側だけを直しても詳細ページの表示は変わらない）。

`_build_match_rounds()` で `roundEndTime` を **HUD 可視の最後の時刻（両サイドの `visibleTo` の大きい方、K.O. で打ち切り）** に変更し、境界そのもの（次ラウンド開始バナー / 試合終了）は `boundaryEndTime` に保持する。

## 検証結果

### 事前検証（サンプリング）

| 動画 | K.O.フレーム | 非 K.O. の最大 IoU |
|------|-------------|-------------------|
| `f36vyEepil4`（既存テンプレ背景） | 22/22（IoU 0.80-1.00） | 0.44 |
| `DSgD_bQhxp0` | 11/11（0.77-0.91） | 0.55（1件、+6秒後） |
| `rNhYCktBpPM`（新背景、roundEnd直前6秒） | **45/50 = 90%**（閾値0.6） | 0.30 |

- ラウンド中の白フラッシュ（`rNhYCktBpPM` 900.25秒）で IoU 0.62 が1回出るが、`min_consecutive = 2` により不採用
- 検出遅延は最大 0.5秒（0.25秒 × 2 サンプル）

### 再処理検証（`rNhYCktBpPM`）

新しい検出で動画全体を再計測した結果:

| 指標 | 変更前 | 変更後 |
|------|--------|--------|
| K.O. 検出数（`koTimes`） | 9 件 | **46 件** |
| ラウンド数不一致の試合 | あり | **0 件**（全20試合で Battlelog と一致） |
| `rNhYCktBpPM_207` R1 end / duration | 263 / 54.55s | **259 / 50.92s** |
| `rNhYCktBpPM_207` R2 end / duration | 318 / 53.47s | **314 / 50.25s** |
| `rNhYCktBpPM_814` R2 end / duration | 993 / 93.41s | **993 / 92.88s** |

ゲージ詳細が使う `gauges/{matchId}.json` のラウンド区間も同様に打ち切られた:

| ラウンド | 変更前（次ラウンドまで） | 変更後（K.O. まで） |
|---------|----------------------|------------------|
| `_207` R1 | 207.75 - 263.75（56.0s） | **207.75 - 259.22（51.5s）** |
| `_207` R2 | 263.75 - 353.00（89.3s） | **263.75 - 314.50（50.8s）** |

## 既知の課題

- 閾値 0.6 は `rNhYCktBpPM` / `f36vyEepil4` / `DSgD_bQhxp0` での実測に基づく。白い背景・白い演出の多いステージでは誤検出の余地が残る
- K.O.文字の表示が短い（連続2サンプル未満）場合は検出できない。`min_consecutive` はトレードオフ
- マスク条件（`S < 70`, `V > 150`）は色収録・配信エンコードの影響を受ける。極端に暗い/明るい配信では再調整が必要
