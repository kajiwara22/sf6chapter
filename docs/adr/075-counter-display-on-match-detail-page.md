# ADR-075: カウンター回数の表示をゲージ詳細ページへ集約する

## ステータス

採用 - 2026-11-04

## 文脈

### 問題

ADR-049 の決定 9 では、ラウンド単位のカウンター / パニッシュカウンター回数を
**対戦履歴のラウンドバッジへの併記**と**ゲージ詳細ページの集計テーブル**の両方に出す設計にしていた。

`0SbYbTsTGSQ`（17 試合 / 44 ラウンド）を Battlelog と突合できるようになった後、
履歴の「ラウンド」列は次のように横長になり、ラウンドの勝敗が読み取りにくくなった。

```
L V C2 PC2 L C1 PC1 P C4 PC1 L C3 PC2 V C3 PC
```

元々この列は「どのラウンドを取ったか / 落としたか」を見るための場所で、
カウンター回数は分析用の補助情報である。同じ情報はゲージ詳細ページの
「ラウンド集計」テーブルにも出ており、履歴に併記する必然性が薄い。

また、履歴のページ読み込みごとに `round_stats` を `matchId IN (...)` で追加クエリしており、
一覧表示のコストにもなっていた。

## 選択肢と結論

| 選択肢 | 内容 | 結論 |
|---|---|---|
| A. 履歴は勝敗のみ、詳細ページに専用セクション | 合計＋ラウンド別内訳を詳細に集約 | **採用** |
| B. 履歴のバッジにツールチップで残す | 見た目は勝敗のみ、hover で回数 | 不採用（タッチ操作で見えない） |
| C. 履歴に別列（試合合計）を追加 | 列が増える | 不採用（一覧の横幅を圧迫する） |
| D. 現状維持 | ADR-049 のまま | 不採用（可読性の問題が残る） |

### A. 履歴は勝敗のみ、詳細ページに専用セクション（採用）

- **対戦履歴**: ラウンド列はラウンドバッジ（V / L / SA / OD / CA / P …）のみ。
  `MatchHistoryRow.roundCounters` と `queryRoundCounters()` の呼び出しを削除する。
- **ゲージ詳細ページ**: ラウンドチャートとラウンド集計テーブルの間に
  「カウンター / パニッシュカウンター」セクションを追加する。
  - 自分・相手の試合合計（カード表示）
  - ラウンド別の内訳（Round × 自分/相手 × カウンター/パニッシュの表）
  - 未計測 `null` は `-`、計測済み 0 件は `0` と区別（ADR-049 の規約を維持）
  - 自分サイドが判定できない場合は `1P` / `2P` 表示
- 既存の「ラウンド集計」テーブルのカウンター列は残す（ラウンド単位の詳細値）。

## 帰結

- 履歴のラウンド列が「取った/落とした」の判断に集中できる長さに戻る。
- 一覧表示時の `round_stats` 追加クエリがなくなる。
- Web のカウンター表示は詳細ページに一本化される（ADR-049 決定 9 を改訂）。
- 共通の表示部品 `formatCounterText` / `createCounterBadge` / `formatCounterCount` は
  `packages/web/src/client/components/CounterBadges.ts` に集約する。
- テスト: `CounterBadges.test.ts` を新設、`MatchHistory.test.ts` は「カウンターを出さない」
  ことを検証、`MatchDetailPage.test.ts` にセクションのテストを追加。
