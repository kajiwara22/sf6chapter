# ADR-065: バーンアウト判定の修正（低ドライブ警告の金色バーと白/銀回復バーの区別）

## ステータス

採用 - 2026-10-14（実装完了 2026-10-14）

## 文脈

### 前提: SF6 のドライブゲージの見え方（ユーザー確認済み）

- ドライブゲージは6本。使うとセルが消える
- **残り2本以下になると、残っているバーが金色/オレンジ（低ドライブ警告）で表示される**。これは残っているドライブであり、**バーンアウトではない**
- ドライブが0になると**バーンアウト**し、ゲージが暗くなる。回復分は常に**白/銀のバー**で、画面中央側（1P=右端 / 2P=左端）から伸びる。満タンになると黄緑に戻る
- バーンアウトした瞬間は金色の「EMPTY」文字が約0.5秒表示される（[ADR-066](066-burnout-empty-banner-detection.md)）

### 問題: ADR-056 の判定が低ドライブ警告をバーンアウトと誤検出していた

ADR-056 の判定は次の2段階だった。

1. 「HUD 表示中に黄緑が検出できない」区間をバーンアウト候補にする
2. 候補区間内で「低彩度・中間明度の画素（回復バー）」が一定割合で観測されたらバーンアウトと確定する

しかし実測すると、この2つには次の欠陥があった。

- 回復バーの指標が**ゲージ ROI 全体の低彩度画素割合**だったため、ゲージ上下の**白い枠線だけで常に閾値を超えていた**（満タンの通常状態でも 0.2 前後）。つまり確定条件がほぼ無条件に成立していた
- 黄緑が検出できない状態は「バーンアウト」だけでなく「**ドライブ1〜2本の低ドライブ警告（金色バー）**」でも起こる。旧実装は黄緑だけを数えていたため、金色バーの状態を「ゲージが空」と誤読していた

この結果、`ovM5BMIsyKw` では 1P 39区間 / 2P 31区間（計70区間・合計454.8秒）がバーンアウトとして記録され、実際のバーンアウト（「EMPTY」文字が出た箇所）は18箇所程度だった。

ユーザーからの具体的な報告:

- `143.9〜151.9`（1P）は**金色1本**だがバーンアウトしていないのに記録されていた（誤検出）
- `914.4s` から始まる（2P）バーンアウトは、実際には**919.4s**（EMPTY文字の時刻）から

### 実測（本 ADR の根拠）

`ovM5BMIsyKw` を 0.1 秒間隔で計測した結果:

| 状態 | 黄緑（通常ゲージ） | 金色（低ドライブ警告） | 白/銀（回復バー・中央側から連続する列） |
|------|------------------|---------------------|--------------------------------|
| 低ドライブ警告（872〜877s 1P） | 0.00〜0.24 | **0.03〜0.22（消えない）** | 0.00 |
| バーンアウト（878〜895s 1P） | **0.000** | **0.000** | 0.00 → 0.53 へ単調に増加 |
| 通常（満タン） | 0.6〜0.9 | 0.00 | 0.00（枠線を除けば 0） |

- ドライブ1〜2本の状態は「**金色を数えれば残量がある**」と分かる
- バーンアウト中は黄緑も金色も 0.000 で、白/銀のバーだけが中央側から伸びる
- ヒット演出の白フラッシュは**単発（0.1〜0.4秒）**で、回復バーのように連続しない

回復バーの明度は実測で V≈150〜180（`ovM5BMIsyKw` のバーは V=177）、全画面の白フラッシュは V≈228〜255 だった（`DSgD_bQhxp0` の誤検出5件はいずれも V 中央値 228〜252、正しい回復バーは V 中央値 155〜167）。この差で両者を分離できる。

## 決定事項

1. **`_measure_drive` は金色バーもドライブ残量として数える**
   - 黄緑: 色相 20〜65 / 彩度 150超 / **明度 135超**（従来どおり）
   - 低ドライブ警告（金色）: 色相 12〜38 / 彩度 150超 / **明度 40〜135**（明度で分離し、二重計上しない）
   - これにより「ドライブ1〜2本」の状態は残量1〜2本として計測され、バーンアウト候補にならない（`driveMin` などの統計も正確になる）
2. **バーンアウト候補** = HUD 表示中 かつ ドライブ残量 < `burnout_candidate_max_drive`（0.5本）
   - ラウンド開始バナーの前後（`burnout_round_banner_before_sec`=1.5秒前〜`burnout_round_banner_after_sec`=3.0秒後）は候補から外す。この区間はゲージがまだ描画されておらず、HUD 可視判定も残るため、明るい背景を回復バーと誤認する（`f36vyEepil4` で8件の短い誤検出）
3. **確定条件** = 候補区間内で次のいずれか
   - **白/銀の回復バーが `burnout_min_bar_sec`（0.5秒）以上連続**して観測される（`drive_recover_min_fraction`=2% 以上の幅）
   - 白の証拠が単発（0.5秒未満）の場合は、**バーンアウト開始の「EMPTY」文字**（[ADR-066](066-burnout-empty-banner-detection.md)）が onset ±1.0秒にあること
4. **区間** = [白/銀の証拠が最初に観測された時刻, ゲージが再び観測される時刻]
   - 低ドライブ警告（金色バー）だけの区間は開始点に含めない
5. **`_measure_drive_recover` を「中央側から連続する白/銀の列」に修正**
   - ゲージ上下の枠（`drive_recover_inset_px`=6）を除いた内側の行だけを使う（枠線による誤検出をなくす）
   - 列の縦方向 60%（`drive_recover_column_fill_ratio`）以上が白/銀の列を、画面中央側から連続する分だけ数える
   - **白飛びの割合が高いフレームは回復バーとしない**（`drive_recover_flash_v_min`=210, `drive_recover_max_flash_fraction`=0.6）。
     実測で回復バーの白飛び率は 0.02〜0.20、バーンアウト開始フラッシュが 0.34〜0.40、全画面の白フラッシュ（ヒット演出・ラウンド移行）は 0.88〜1.00 だった。
     明度の上限を 210 で切る案（白飛び画素を全除外）も試したが、実際の回復バーは V>210 のハイライトを約2割含むため列充填率を満たせず、本物のバーンアウトを 2 件失った。
     そのため「白飛びが過半なら演出」という判定にした
6. `burnout_recover_min_ratio`（ADR-056 の比率条件）を削除

## 結果

### 良い点

- ユーザー報告の誤検出（金色1本でのバーンアウト記録）がなくなり、開始時刻も実際のバーンアウト（EMPTY文字・白フラッシュ）と一致する
- ドライブ残量の計測値が正確になる（低ドライブ警告の金色バーも残量として計上）
- 「HUD 表示中に黄緑が無い」だけでは判定できない、という ADR-056 の課題を根本から解消した

### 検証（`ovM5BMIsyKw` 1944秒 / 13試合）

| 指標 | 旧（ADR-056 実装） | 新 |
|------|-------------------|-----|
| バーンアウト区間数 | 1P 39 / 2P 31（計70） | **1P 7 / 2P 11（計18）** |
| 合計秒数 | 1P 217.3 / 2P 237.5 | 1P 90.3 / 2P 163.6 |
| 既知のバーンアウト（EMPTY文字 18箇所） | 15/70区間が一致 | **18/18箇所を検出**（開始時刻は 2 箇所を除き EMPTY 文字と一致） |
| `143.9〜151.9`（1P, 金色1本の誤検出） | 記録されていた | **消滅** |
| `748.4〜758.6`（ヒット演出の白による誤検出） | 記録されていた | **消滅** |
| `914.4s` 開始（2P, 実際は 919.4s） | 5秒早い | **919.4s**（開始フラッシュ） |
| `1170.2` / `298.0`（短いバーンアウト） | 未検出 | **検出**（1170.0〜1173.9 / 297.7〜302.2） |

### 検証（`DSgD_bQhxp0`）

| 指標 | 旧（ADR-056 実装） | 新 |
|------|-------------------|-----|
| バーンアウト区間数 | 1P 79 / 2P 69（計148） | **1P 16 / 2P 17（計33）** |
| 合計秒数 | 943.7s | 445.6s |
| 短区間（≤2秒） | 52件 | ほぼ消滅 |

- ADR-056 の既知課題「回復バーが黄緑に近く見える」は再現せず、実際の回復バーは S 中央値 10〜20・V 中央値 155〜164 で白/銀として正しく検出できた
- 全画面の白フラッシュによる誤検出（1P `222.6`（FINAL ROUNDバナー）, `2890.5`, `2926.4`、2P `601.2`, `1428.4`）は決定5の白飛び判定で消滅
- 白飛び率の実測値（本 ADR の閾値の根拠）: 回復バー 0.02〜0.20 / 全画面フラッシュ 0.88〜1.00

| 指標 | 旧（ADR-056 実装） | 新 |
|------|-------------------|-----|
| バーンアウト区間数 | 1P 81 / 2P 63（計144） | **1P 10 / 2P 14（計24）** |
| 合計秒数 | 855.3s | 約382s |
| round_stats の burnoutCount 合計 | 170 | **約24** |
| burnoutSec 20秒超 | 36件（ADR-056 の記録と一致） | **9件** |
| 区間長の中央値 | 2.7秒 | **約18秒**（真のバーンアウトは13〜24秒） |

- ラウンド開始バナーの前後を候補から外す修正（決定2）で、ゲージ未描画の明るい背景による短い誤検出（1.7〜1.9秒が6件）が消えた
- 残る短い誤検出: 231.3s（コンボ演出の暗転）と約1970s（原因不明）の2件（いずれも EMPTY 文字も回復バーもない）

### 制約・トレードオフ

- ゲージが白色/金色/黄緑のいずれでもない暗い状態（背景が映り込むラウンド遷移や演出）は「空」と判定される。`hud_visible`（SA 数字のスコア）、ラウンド開始バナーの前後除外、最小継続時間 1.0 秒、白飛び率による演出除外である程度は防いでいるが、完全ではない（`f36vyEepil4` の 231.3s・約1970s など）
- 閾値は `ovM5BMIsyKw` で決めた。動画間で金色の明度・色相がずれる場合は `drive_low_filled_*` の調整が必要（ADR-056 の「動画間の色差」課題と同種）

### 既知の課題

- 1回のバーンアウトが2区間に分かれることがある（例: 1P `515.6〜517.1` と `519.7〜542.2`）。回復途中でドライブが一瞬読めた場合に候補区間が切れるため
- EMPTY 文字を検出できなかった場合（`ovM5BMIsyKw` 2P `1690.5` など）、開始時刻が回復バーの検出時刻まで数秒遅れる
- 閾値はこの 3 本（`ovM5BMIsyKw` / `DSgD_bQhxp0` / `f36vyEepil4`）で確認した。他動画での回帰確認を継続する
