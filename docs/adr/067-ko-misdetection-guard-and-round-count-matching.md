# ADR-067: K.O. 誤検出の抑制とラウンド数整合による Battlelog マッピング補正

## ステータス

採用 - 2026-10-17

## 文脈

`rf-kzjE9mTk`（36:59、17試合）の解析で、ゲージ詳細のラウンドデータに 2 種類の不整合が判明した。

### 問題1: ラウンド開始直後の K.O. 誤検出で durationSec が破壊される

- `round_stats` 84 行のうち 30 行（15 ラウンド、35.7%）で `durationSec < 10秒`（同じ動画の中央値は 29.5 秒）
- 例: `rf-kzjE9mTk_561` の R1 が `durationSec = 2.45秒`
- 原因は ADR-063 の白/銀マスク照合（閾値 0.6、`min_consecutive = 2`）が、**ラウンド開始バナー直後の画面を K.O. と誤検出**していたこと

実測した `_ko_color_score`:

| 時刻 | 種別 | スコア |
|---|---|---|
| 193.75 | 真の K.O. | 0.785〜0.849 |
| 235.50 | 真の K.O. | 0.682〜0.693 |
| 275.50 | 真の K.O. | 0.658〜0.758 |
| 367.75 | 誤検出（ROUND 1 バナー直後） | 0.638〜0.641 |
| 372.50 | 誤検出 | 0.602〜0.631 |
| 382.00 | 誤検出 | 0.602〜0.607 |
| 564.50 | 誤検出 | 0.629〜0.636 |
| 657.25 | 誤検出 | 0.630〜0.638 |

白い服装（ARJUN の白ズボン）と明るい壁ステージの組み合わせで、K.O. 文字のシルエットと 0.6 台で一致してしまう。閾値 0.6 を超えると 2 連続（0.25 秒間隔）で K.O. が確定し、`_visible_range` が `ko_time` 以降の可視を打ち切るため、ラウンドの実効終了が開始直後に張り付く。

石畳の暗いステージ（`rf-kzjE9mTk_134` など）では誤検出せず、`durationSec` は正常だった。

### 問題2: チャプター数が Battlelog より 1 つ少なく、割当が 1 つずれる

- ROUND / FINAL ROUND バナーは合計 44 個。FINAL ROUND（12 件）は常にその試合の 3 ラウンド目なので、バナー列は **17 試合**を成す
- チャプター検出は **16 試合**。先頭試合の ROUND 1（30.25 秒）が閾値ギリギリで未検出だった
  - 動画 30.6 秒のマッチスコアは **0.532**（`threshold = 0.55` 未満）。134 秒は 0.556 で検出
- Battlelog は **17 件**
- マッチングは「キャラクター一致 + 時刻差最小」で選ぶため、チャプター 134 秒に 1 つ前のリプレイが割り当たり、以降がすべて 1 つずれる
- 結果として `round_count mismatch` が 6 件（`match/mismatch/unknown = 10/6/0`）
- さらにキャラクター認識誤り（1481 秒の TERRY を CHUN-LI と誤認）が重なるとキャラ一致が崩れ、未マッチが発生する

バナーと Battlelog のラウンド数を時系列で並べると、先頭を 1 つずらせば完全に一致する（2,3,2,2,2,3,3,3,3,3,3,3,3,2,2,3,2）。

## 決定

### 1. K.O. マスク閾値を 0.60 → 0.65 に引き上げる

実測で真の K.O.（0.658〜0.849）と誤検出（0.602〜0.641）が分離できる。`config/detection_params.json` の `gauge_analysis.ko_color_mask.threshold`。

### 2. ラウンド開始直後の K.O. 検出を無視する（`ko_start_guard_sec = 5.0`）

`_round_ko_time` で「ラウンド開始 + 5 秒」未満の K.O. 検出を無視する。真に HUD が消えた場合は `_visible_range` の途切れ判定（`round_end_gap_sec = 5.0`）が終端を決めるため、終端検出そのものは失われない。

### 3. チャプター区間の ROUND バナー数で Battlelog の `round_count` を照合する

- チャプター区間 `[startTime - 1.0, nextStartTime - 1.0)` に含まれる ROUND バナー数を「動画側のラウンド数」とする（チャプター `startTime` は int 丸めされるため 1 秒の許容を持たせる）
- 一致しない候補には 1000 秒のペナルティを課し、一致する候補を優先する
- キャラクター一致候補が無い場合は、**ラウンド数が一致する候補を救済として採用**する（認識誤りでキャラ一致が崩れても、以降の割当が 1 つずれないようにする）

バナー時刻が取れない場合（ゲージ計測無効）は従来どおりキャラ一致 + 時刻差最小で動作する。

### 4. チャプタータイトルを Battlelog のキャラクター名に揃え、YouTube 更新をマッチング後に行う

- 救済候補を採用したチャプターは、タイトル（Gemini の認識結果）と Battlelog のキャラクターが食い違う。マッチしたチャプターのタイトルを正規化済みの Battlelog 名で再構成し、表示とデータを一致させる
- 従来は YouTube チャプター更新が Battlelog マッチングより先にあったため、補正後のタイトルが YouTube に反映されなかった。マッチング後に更新するよう順序を入れ替える

## 帰結

### 検証結果

`rf-kzjE9mTk`（ゲージ再計測 + 再処理）:

- `durationSec < 10秒`: 30 行 → **0 行**。正常だったラウンドの値は変化なし
- K.O. 検出数: 90 件 → 40 件（誤検出 50 件を除去）
- Battlelog マッチ: 16/16（100%）。救済候補の採用は 4 件（1041 / 1481 / 1792 / 1904）
- `round_count mismatch`: 6 件 → **0 件**
- チャプターのラウンド数と Battlelog の `round_count` は全 16 試合で一致
- チャプタータイトルも Battlelog に揃い、認識誤り 4 件が補正された
  （1481: CHUN-LI → TERRY、1792: TERRY → JURI、1904: JURI → JP、1041: ARJUN → CHUN-LI）

`DSgD_bQhxp0`（ゲージ再計測のみ、横断確認）:

- `durationSec < 10秒`: 8 行 → **0 行**。正常ラウンドはほぼ不変（1 件のみ 43.91 → 44.36 秒）

### トレードオフ

- K.O. 閾値を上げると、白/銀マスクが薄い真の K.O. を落とす可能性がある。落ちた場合は HUD 途切れ判定が終端を決めるため `durationSec` は概ね維持されるが、勝利演出中の health 誤読を抑える効果は弱まる
- 救済候補（キャラ不一致）はラウンド数一致を必須とするため、誤マッチのリスクは限定的

### 未解決・将来の見直し

- **先頭試合の検出漏れ**（マッチスコア 0.532 が閾値 0.55 未満）。検出閾値の変更は他動画への影響検証が必要
- **キャラクター認識誤り**（TERRY → JURI、JURI → JP など）。ADR-042 の認識精度課題。
  救済候補とタイトル補正で実害は抑えたが、認識自体の改善が必要
- 白/銀マスクの背景汎化（白い服装・明るいステージ）は引き続き課題
