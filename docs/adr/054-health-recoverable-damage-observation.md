# ADR-054: 回復可能ダメージ（白ゲージ）の観測と回復ゲート

## ステータス

採用 - 2026-10-11

## 文脈

### 前提: SF6 で体力が増える条件

SF6 でラウンド中に現在体力が増えるのは、次の 2 つだけである。

1. **回復可能ダメージ（白ゲージ）の自然回復**
   - ドライヴインパクトのアーマー受けなど特定の防御・被弾で発生する。
   - 体力バー上では「現在体力（キャラクター色）の外側（空きトラック側）に隣接する帯」として描画される。
2. **エレナの SA2**（回復可能分に依存しない直接回復）

したがって「回復可能ダメージが無いのに現在体力が増える」ことは、ゲーム上ありえない。

### 問題: ありえない回復が記録される

ADR-050 の実装は現在体力の列数だけを％化し、増加は `health_max_increase_per_sec = 5.0`（%/秒）でしか制限していなかった。
そのため、次の 2 種類の誤りがそのまま「回復」として残っていた。

- **一時的な遮蔽・ヒット演出による低値**: 体力バーがエフェクトで隠れると現在体力を低く誤読し、直後に元の値へ戻る。低下は制限されないため、この「戻り」が回復として記録される。
- **半透明トラックの誤検出**: 空きトラックは半透明でステージが透けるため、明るいステージ上では空き部分が現在体力色（暗いマゼンタ等）に近い値になり、V 閾値（110）を超えて現在体力に数えられる。

実例（`DSgD_bQhxp0` / `_278` round 3）:

| 時刻(絶対) | 生サンプル | 変化点JSON（旧） |
|-----------|-----------|-----------------|
| 400.0 | 99.1% | 99.1% |
| 400.1 | （遮蔽で約 58% と誤読） | **57.8%** |
| 406.0 | 90.9% | **90.4%** |

この「57.8% → 90.4%」は回復可能ダメージの減少を伴っておらず、ゲーム上ありえない回復だった。

### 実測（本 ADR の根拠）

`download/20261006[DSgD_bQhxp0].mp4`（1920x1080）で体力バーを列単位に解析した。

- 現在体力（P1）: H≈170, S≈230, V≈180〜215（明るいマゼンタ）
- 空きトラック（P1, 明るいステージ上）: H≈178, S≈237, V≈116〜122（暗いマゼンタ）
- 回復可能ダメージ: H≈24, S≈115〜180, V≈150〜250（黄〜オリーブ）。現在体力の**外側**に隣接して現れる（t=406.0 で列 7〜96、現在体力は列 98〜686）
- t=175（残体力 1.5%）では現在体力の内側寄りに黄色帯（列 ≈617）を確認

空きトラックが半透明であるため、**色だけでは回復可能ダメージと背景を分離できない**。
一方、回復可能ダメージは常に現在体力に隣接しているため、位置（隣接）で分離できる。

## 決定

### 1. 回復可能ダメージを別系列として計測する

- ROI 内の回復可能色（黄〜白）を数えるのではなく、**画面中央側のアンカーから「現在体力 → 回復可能」の順に連続する帯**だけを数える。
  - アンカーは ROI の中心が画面中心より左なら右端（1P）、右なら左端（2P）
  - これにより、現在体力に隣接しない背景の黄を除外する
- 色域は `health_recoverable_hue_ranges`（既定: 黄 `[[15, 50]]`）と `health_recoverable_v_min` / `health_recoverable_s_min` で設定する
- 現在体力と同じ平滑化（メディアン＋短い欠損補完）をかける

### 2. 回復ゲート: レート上限＋回復可能分の上限

- 現行の `health_max_increase_per_sec`（5%/s）は維持する
- 追加で、**直前サンプルから減った回復可能分の範囲だけ**増加を許可する

```
rate_delta      = health_max_increase_per_sec * elapsed
available_delta = max(0, previous_recoverable - recoverable)
max_allowed     = previous_health + min(rate_delta, available_delta)
```

- 回復可能分が減っていないのに増える値は計測ノイズとみなし、前値で保持する

### 3. 一時的な低値（遮蔽・ヒット演出）の除去

- 体力の平滑化後に、`health_despike_revert_sec`（既定 1.2 秒）以内に直前値以上へ戻る下振れを前値で塗り直す
- 実際の被弾は永続的で、回復も秒単位なので、1.2 秒以内の即復帰はノイズと判断できる
- SA ストックの下振れ除去と同一の関数（`_suppress_transient_reverts`）を共用する

### 4. エレナの SA2 はゲートの例外

- キャラクター名が `ELENA` かつ、そのラウンドで SA ストックを消費（＝スーパーアーツ発動）していれば、回復ゲートを無効化する
- 直接回復は回復可能ダメージに依存しないため

### 5. 保存と表示

- `gauges/{match_id}.json` の各サイドに `healthRecoverable`（`[経過秒, 回復可能%]` の変化点列）を追加する
- `gauges_samples.csv` に `health_recoverable` / `health_recoverable_raw` 列を追加する
- Web の体力チャートに回復可能ダメージを破線で重ねる（旧データは `undefined` で非表示）
- `round_stats.parquet` の列は追加しない（回復可能は時系列の参考情報として扱う）

### 6. 適用範囲は ADR-048/050 と同じ

- 新規動画は本線パイプラインで自動計測する
- 既存動画は `scripts/analyze_gauges.py --video-id <id>` で再処理する（`matches.json` からキャラクター名を読み、エレナ例外に使う）

## 選択肢の比較

### 回復の制限方法

| 方式 | 挙動 | 判定 |
|------|------|------|
| A. 現行のレート上限のみ | 遮蔽ノイズが回復として残る | 不採用 |
| B. レート上限＋回復可能分の上限 | 説明できない増加を除去できる | **採用** |
| C. 増加を一切禁止 | エレナの SA2 や実際の回復も消える | 不採用 |

### 回復可能ダメージの計測

| 方式 | 挙動 | 判定 |
|------|------|------|
| A. ROI 内の回復可能色を数える | 半透明トラック越しの背景を誤検出する | 不採用 |
| B. 現在体力に隣接する帯だけを数える | 背景の黄を除外できる | **採用** |
| C. 回復可能を計測せず増加を禁止 | エレナ以外の回復も消える | 不採用 |

## リスクと対策

| リスク | 内容 | 対策 |
|--------|------|------|
| 回復可能色の誤り | 実際の描画が黄ではなく白／灰の可能性がある（利用者見解）。白／灰は半透明トラックと区別できない | 色域を設定で変更可能にする。実測では黄〜オリーブが現在体力に隣接して現れる |
| 残体力が極端に低いときの背景誤検出 | バーが空に近いとステージが広く透ける | 隣接帯のみを数える。`health_recoverable_v_min` / `s_min` で調整可能 |
| 回復の過剰抑制 | 回復可能の計測漏れがあると本当の回復も抑える | レート上限は維持し、回復可能が検出された区間は許可する |
| エレナ以外の回復技 | 将来キャラクターが追加された場合 | 例外キャラクターを定数（`ELENA`）で管理し、必要なら拡張する |
| 旧データとの互換 | `healthRecoverable` が無い過去の JSON | Web は `undefined` を空系列として扱い、例外にしない |

## データモデル（ADR-050 からの差分）

`gauges/{match_id}.json` の各サイド:

```json
{
  "player1": {
    "healthCoverage": 0.94,
    "health": [[0.62, 100.0], [3.14, 89.4], [7.05, 76.2]],
    "healthRecoverable": [[3.2, 12.0], [5.0, 6.0], [7.0, 0.0]]
  }
}
```

- `healthRecoverable`: `[ラウンド開始からの経過秒, 回復可能ダメージ%]` の変化点列（閾値 1.0%）
- 既存フィールドは変更なし（後方互換）

| `tests/test_gauge.py` / `packages/web` | 回復可能計測・回復ゲート・エレナ例外・despike・Web 描画のテスト |

実動画（`DSgD_bQhxp0` 先頭 130 秒）での確認:

- round 1 の「28.4% → 52.4%」という回復は消え、`22.43 (31.8%) → 30.45 (3.6%)` に整理された
- `healthRecoverable` は 1 ラウンドあたり数件に収まり、残体力が高い区間では空（`[]`）になった

手元 3 本への適用（2026-10-11。R2 反映済み）:

| 動画 | ラウンド | 体力変化点 | 体力の増加 | 回復可能系列 | 回復可能変化点 |
|------|---------|-----------|-----------|-------------|--------------|
| `DSgD_bQhxp0` | 51 | 2694 → 1360 | 633 → 66 | 102 | 439 |
| `JzKWGcwFt2w` | 33 | 1779 → 1101 | 399 → 48 | 66 | 370 |
| `Ndwu08Q--_M` | 27 | 1285 → 785 | 263 → 21 | 54 | 192 |

（ラウンド数は ADR-052 の FINAL ROUND 検出適用後の値。`JzKWGcwFt2w` は 26→33、`Ndwu08Q--_M` は 24→27 に修正された）

スポットチェックした体力の増加は、いずれも直前の回復可能分（例: `_20` R1 p1 の `3.6→20.0` は回復可能 16.5）で説明できる範囲に収まっていた。
