# ADR-066: バーンアウト開始の「EMPTY」文字検出による確証

## ステータス

採用 - 2026-10-14（実装完了 2026-10-14）

## 文脈

### 発端

ユーザー確認により、SF6 は**バーンアウトした瞬間に金色の「EMPTY」を約0.5秒表示する**ことが分かった（毎回表示される）。表示位置は各プレイヤーのドライブゲージの内側（画面中央寄り）で、1P/2P で位置が異なる。

[ADR-065](065-burnout-low-drive-warning-vs-recover-bar.md) の「空ゲージ＋白/銀の回復バー」でも大半のバーンアウトは判定できるが、次の2点が残っていた。

1. **ヒット演出の白フラッシュと回復バーの区別**: `ovM5BMIsyKw` の `748〜758秒` は低ドライブ警告（金色バー）の状態でヒット演出の白が重なり、回復バーと誤認してバーンアウトとして記録されていた
2. **開始直後の回復バーは細い**: バーンアウト直後の回復バーは幅数ピクセルで 0.5 秒の連続検出に届かないことがある（この場合は白フラッシュが証拠になるが、フラッシュだけでは上記 1 と区別できない）

「EMPTY」文字はドライブゲージの色とは独立した信号であり、低ドライブ警告（金色バー）では**出ない**ため、強い確証になる。

## 決定事項

1. **金色文字のマスク照合で「EMPTY」文字を検出する**（[ADR-063](063-ko-banner-white-mask-detection.md) の K.O. 文字と同じ考え方）
   - 探索領域（base 1920x1080 基準、フレームサイズに比例拡大）: 1P `(740, 100)-(910, 140)` / 2P `(1010, 100)-(1180, 140)`
   - 金色マスク: 色相 8〜35 / 彩度 110以上 / 明度 215以上（低ドライブ警告の金色バーより明るい）
   - テンプレート: `template/burnout_empty_player1.png` / `burnout_empty_player2.png`
     （実フレームから切り出した金色マスクの二値画像。0.85 / 1.0 / 1.18 倍で照合し、文字の拡大アニメーションを吸収する）
   - 判定は2つの指標の両方が閾値以上であること
     - **coverage** = 一致画素数 / テンプレート面積（≧0.4）: 文字の形がそこにあるか
     - **precision** = 一致画素数 / 探索領域の金色画素数（≧0.6）: 領域の金色をテンプレートで説明できるか
       （大きな金色の塊＝低ドライブ警告の金色バーや全画面の金色演出は precision が下がるため除外される）
   - `min_consecutive`=2 回を `consecutive_window_sec`（0.3秒）以内に検出した時点で最初の時刻を記録する
     （EMPTY 文字は約0.5秒しか出ないため、アニメーション位相によっては連続フレームで拾えないことがある）
   - **両サイドで 0.3 秒以内に検出されたものは全画面演出**として除外する（バーンアウトは同時に両者には起きない）
2. **ADR-065 の確定条件に組み込む**: 候補区間（空ゲージ）内に「EMPTY」文字があればバーンアウトと確定する。
   また開始時刻は、回復バーの最初の検出時刻と EMPTY 文字の時刻の**早い方**を採用する（回復バーは細く、数秒遅れて検出されることがある）。低ドライブ警告（金色バー）の区間には文字が出ないため誤検出しない
3. 検出時刻を `gauges.json` の `burnoutBannerTimes` に出力する（検証・デバッグ用）

### 実装

- `packages/local/src/detection/gauge.py`
  - `BurnoutBannerParams`（`coverage` / `precision` / `scales` / `min_consecutive` / `onset_tolerance_sec` / `same_time_tolerance_sec`）
  - `_gold_mask()`: 高輝度の金色を二値マスク化
  - `_detect_burnout_banner()`: マスク照合・連続検出・記録・スナップショット
  - `_effective_burnout_banner_times()`: 両サイド同時検出（全画面演出）の除外
  - `feed()` からサンプリング周期（0.1秒）で呼び出す
- `packages/local/config/detection_params.json`: `gauge_analysis.burnout_banner` を追加
- `packages/local/template/burnout_empty_player{1,2}.png`: テンプレート（実フレームから生成）

## 結果

### 良い点

- ヒット演出の白フラッシュによる誤検出（`748〜758秒` など）がなくなり、開始時刻も実際のバーンアウトと一致する
- 「EMPTY」文字は低ドライブ警告では出ないため、判定の確度が大きく上がる

### 検証（`ovM5BMIsyKw` 1944秒）

| 指標 | 結果 |
|------|------|
| 検出した「EMPTY」文字 | 1P 6件 / 2P 10件（計16件） |
| 誤検出 | **0件**（16件すべてが既知のバーンアウト開始と一致） |
| 取りこぼし | 2件（1P 990.2 / 2P 919.5）。文字がアニメーションの中間位相でしか検出できず、閾値を満たすフレームが1枚しかなかった |
| バーンアウト区間数（旧→新） | 1P 39→7 / 2P 31→11 |

### 検証（`DSgD_bQhxp0`）

| 指標 | 結果 |
|------|------|
| 検出した「EMPTY」文字 | 1P 16件 / 2P 15件（計31件） |
| 検出時刻がバーンアウト区間内にある割合 | **31/31（100%）** |
| 開始時刻（onset）との一致（±1.0秒） | 22/43区間（残りは白バーが先に検出された区間、または文字の検出漏れ） |

### 制約・トレードオフ

- テンプレートは `ovM5BMIsyKw` から生成した。ゲーム UI は共通なので他動画でもそのまま使える想定だが、表示位置・明るさがずれる場合は探索領域とマスク閾値の調整が必要
- 文字が演出で隠れる／アニメーション位相によっては coverage が閾値未満になることがある（上記の取りこぼし）。その場合でも白バー経路でバーンアウト自体は検出できるが、開始時刻が回復バーの検出時刻（数秒後）にずれる
- 単発の金色演出を除外するために検出2回を要求しているため、文字が完全に1フレームしか見えない場合は検出できない
