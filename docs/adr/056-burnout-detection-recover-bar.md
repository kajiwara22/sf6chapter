# ADR-056: バーンアウト判定の白/グレー回復バー検出による高精度化

## ステータス

採用 - 2026-10-12（実装完了 2026-10-12）

## 文脈

### 前提: SF6 のドライブゲージとバーンアウト

- ドライブゲージは黄緑色のセグメント（6本）で、ドライブラッシュ（3本）や OD 必殺（2本）等で一瞬で数本消費する。2回続ければ即バーンアウトになりうる。
- バーンアウトするとゲージ全体が暗くなり、回復が進むと**白/グレーの回復バー**が溜まる（1P は右→左、2P は左→右）。回復完了で黄緑に戻る。
- したがって「黄緑が検出できない」こと自体はバーンアウトの必要条件ではあるが、十分条件ではない。

### 問題: 非現実的な burnoutSec の誤検出

ADR-048 の実装は「HUD 表示中に黄緑が検出できない状態」をそのままバーンアウトとみなしていた。このため次の 2 種類の誤りがバーンアウトとして記録されていた。

1. **ラウンド開始直後のゲージ未表示**: ROUND バナー表示中〜 FIGHT でゲージが表示されるまでの数秒は黄緑が存在しない。
2. **プレイ中の黄緑検出の不安定さ**: ドライブゲージの黄緑がフレーム間で検出/非検出を繰り返す（光沢・エンコードノイズ・ゲージ消費で細くなる等）。

実測（`f36vyEepil4` の round_stats、旧実装）:

| 指標 | 値 |
|------|-----|
| burnoutSec 平均 | 14.9 秒 |
| burnoutSec 中央値 | 12.3 秒 |
| 20 秒超のラウンド×サイド | 36 / 108 件 |
| 最大値 | 57.8 秒 |

SF6 のバーンアウトは通常 5〜10 秒（回復中に被弾すると延びるが 15 秒超は稀）であり、明らかに過大評価されていた。

### 実測（本 ADR の根拠）

`download/20261011[f36vyEepil4].mp4`（1920x1080）で、ユーザーが目視で特定したバーンアウト区間（54 秒直後〜74 秒、1P 側）を解析した。

- 満タン時（42 秒）の黄緑ピクセル: H 中央 35（範囲 6〜62）、S 中央 234、V 中央 177。**旧閾値（H25-60 / S>100 / V>150）は低明度側を約 10% 取りこぼしていた**。
- バーンアウト中の回復バー（55〜70 秒）: 右側 20% が**低彩度・中間明度**（S 41〜78、V 102〜148）の白/グレー。バーンアウト直後（55 秒）はまだ暗く（BGR `[27,32,64]`）、時間とともに白くなる。
- 通常時の空きトラック（50 秒）: **高彩度・低明度**（S 198、V 84）で、回復バーとは分離可能。

## 決定

### 1. 黄緑検出の閾値を実測に合わせて調整する

| パラメータ | 旧 | 新 |
|-----------|-----|-----|
| `drive_filled_v`（明度下限） | 150 | **135** |
| `drive_filled_s`（彩度下限） | 100 | **150** |
| `drive_filled_h_min` | 25 | **20** |
| `drive_filled_h_max` | 60 | **65** |

- 彩度下限を上げたのは、バーンアウト中の赤い縁（中彩度）を黄緑と誤認するのを防ぐため。
- この調整により、残り 1〜2 本のドライブゲージも検出できるようになった（`f36vyEepil4` 50 秒で drive=1.61 本）。

### 2. 白/グレー回復バーの検出を追加する

`_measure_drive_recover()` を新設し、ドライブゲージ ROI 内の「低彩度・中間明度」ピクセル割合を計測する。

| パラメータ | 値 |
|-----------|-----|
| `drive_recover_v_min` / `drive_recover_v_max` | 100 / 210 |
| `drive_recover_s_max` | 100 |
| `drive_recover_min_fraction` | 0.02 |

### 3. バーンアウト判定を「黄緑なし＋回復バーあり」に変更する

- 旧: `hud表示中 && 黄緑なし` が `burnout_min_duration_sec` 以上続いた区間 → バーンアウト
- 新: `hud表示中 && 黄緑なし` の区間をまず候補とし、その区間内で**回復バーが観測されたサンプルの割合が `burnout_recover_min_ratio`（0.3）以上**の区間だけをバーンアウトと確定する

これにより、ラウンド開始直後のゲージ未表示（黄緑なしだが回復バーも無い）と、黄緑の瞬間的な検出漏れがバーンアウトから除外される。

## 検証結果（`f36vyEepil4`、108 ラウンド×サイド）

| 指標 | 旧 | 新 |
|------|-----|-----|
| burnoutSec 平均 | 14.9 秒 | **7.9 秒** |
| burnoutSec 中央値 | 12.3 秒 | **3.5 秒** |
| 20 秒超の件数 | 36 件 | **18 件** |
| 最大値 | 57.8 秒 | 32.5 秒 |

burnoutSec が減少したのは 84/108 件（78%）。中央値 3.5 秒は SF6 のバーンアウトとして妥当な範囲に収まった。

## 既知の課題

- **20 秒超が 18 件残る**: `f36vyEepil4_1304` R1 player1 29.0 秒など。実バーンアウト（回復が遅れた）か誤検出かの目視確認は未実施。
- **動画間の色差**: `DSgD_bQhxp0` ではバーンアウト中の回復バーが黄緑に近い色に見え、黄緑がわずかに検出される（drive 0.2〜1.4 本）。このため同動画ではバーンアウトがやや過小評価される傾向がある。固定閾値の限界であり、動画ごとのキャリブレーションは将来課題とする。
