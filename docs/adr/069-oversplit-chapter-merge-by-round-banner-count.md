# ADR-069: 試合中のラウンド開始画面の誤検出による過分割チャプターの統合

## ステータス

採用 - 2026-10-29

## 文脈

`F16OBc27nSc`（43分1秒、`スト６ランクマ 26/10/29`）の解析で、検出試合数が Battlelog より
1 つ多い不整合が発生した。

### 症状

- 試合検出は **18 件**、Battlelog のリプレイは **17 件**
- Battlelog マッチは 17/18（94%）。`F16OBc27nSc_1456` が未マッチ
- `round_count mismatch` が 2 件
  - `F16OBc27nSc_1314`: 動画側 2 ラウンド / Battlelog 3 ラウンド
  - `F16OBc27nSc_1402`: 動画側 1 ラウンド / Battlelog 3 ラウンド

### 原因

1402 秒の検出は**試合開始（VS 画面）ではなく、試合中のラウンド開始画面**だった。

- 保存フレーム `frame_010_1402s.png` はキャラクター名の表示が無い通常の対戦画面
- テンプレートマッチスコアは 0.555（正しい試合開始は 0.55〜0.63 程度で、スコアでは分離できない）
- ROUND バナー列を見ると 1406.75 秒に ROUND バナーがあり、1402 秒はその僅か手前
  （3 ラウンド目の開始演出中）

この過分割により、`1314`（本来 3 ラウンド）が `1314`（2 ラウンド）と `1402`（1 ラウンド）に
分割された。`1402` が Battlelog の `A37TXSALU`（3 ラウンド）を先に確保したため、
本来の試合である `1456` が未マッチになった。

ADR-067 の round_count 照合は「候補の優先順位」を付けるだけで、**余分なチャプターを削除しない**。
そのため過分割が残ると、以降の割当がずれたままになる。

## 決定

**区間内の ROUND バナー数が 1 つしか無いチャプターを、同じカードの隣接チャプターへ統合する。**

### 判定条件

- チャプター区間 `[start_i - 1.0, start_{i+1} - 1.0)` に含まれる ROUND バナー数を数える
  （ADR-067 の `_expected_round_counts` をそのまま使う）
- バナー数が **1** のチャプターを過分割とみなす。SF6 は 2 本先取のため、1 試合に
  ROUND バナーは最低 2 つ存在する。1 つしか無い区間は原理的に試合として成立しない
- 統合先は**同じカード（チャプタータイトルが一致）**の隣接チャプターに限る。
  カードが違う場合はキャラクター認識の誤りと区別できないため統合しない
- バナー数が 0（未検出）の区間は判定不能として統合しない（ADR-067 の「バナーが 1 つも無い
  区間は None」と同じ扱い）

### 実行タイミング

ゲージ計測（ADR-048）の `build()` **前**に実行する。

- 補正後の試合範囲でラウンド分割が行われるため、`round_stats` と `gauges` が最初から正しくなる
- 動画の再デコードは不要（検出・ゲージ走査は 1 回のまま）
- 削除した検出は `matches` / `detections` / 保存する `detection_summary.json` からも取り除く

## 選択肢の比較

| 選択肢 | 内容 | 評価 |
|---|---|---|
| A | 誤検出フレームを除外テンプレートに追加する（ADR-017 の仕組み） | × 対戦中の画面は多様で、1 枚のテンプレートでは汎用性が無い。正常な検出を巻き込むリスクが高い |
| B | 検出閾値を上げる（0.55 → 0.6 以上） | × 正しい試合開始（0.55〜0.63）を落とす。ADR-067 でも閾値変更は他動画への影響検証が必要とされている |
| C | Battlelog の round_count と合わない区間を自動削除 | △ Battlelog が取得できない場合に動作しない。また「どの隣接区間と統合するか」が決まらない |
| D | ROUND バナー数 1 の区間を同カードの隣接区間へ統合（採用） | ◎ Battlelog 不要。2 本先取というゲーム仕様に基づくため誤判定が少ない。ゲージ build 前に実行でき、再デコードも不要 |

## 帰結

### 検証結果

`F16OBc27nSc`（本線フロー `--video-id` で再処理）:

- 検出 18 件 → **17 件**（`F16OBc27nSc_1402` を自動統合）
- Battlelog マッチ: 17/18（94%）→ **17/17（100%、すべて confidence=high）**
- `round_count mismatch`: 2 件 → **0 件**
- `F16OBc27nSc_1314`: 2 ラウンド → **3 ラウンド**（`detectedRoundCount=3` / `battlelogRoundCount=3`）
- `F16OBc27nSc_1456`: 未マッチ → **`A37TXSALU` にマッチ**
- `round_stats` 88 行 / 17 試合 / 44 ラウンド、YouTube チャプター 17 章

### トレードオフ

- **バナー検出漏れとの区別**: 正当な試合でも ROUND バナーが片方しか検出されなければ
  バナー数 1 になる。その場合、同じカードの隣接試合と統合されてしまう
  （例: 同一キャラとの連戦で、2 ラウンド目のバナーが未検出）
- 対策として統合先を「同じカード」に限定しているが、同一キャラとの連戦では区別できない。
  ただし ROUND バナーは `threshold=0.35` と低く、検出漏れは稀（ADR-067 の実測では 44 バナー中
  未検出は先頭 1 件のみ）
- 過分割が連続する場合（1 バナーの区間が 2 つ並ぶ）は、1 つずつ順に統合する

### 未解決・将来の見直し

- 同一キャラとの連戦で「バナー検出漏れ」と「過分割」を取り違える可能性は残る。
  Battlelog の `round_count` が取得できる場合は、統合後に round_count が一致することを
  確認する二段目の検証を入れる余地がある
- 誤検出そのもの（試合中のラウンド開始画面が試合開始テンプレートに 0.555 で一致する）は
  残っており、本 ADR は事後補正である
