# ADR-070: レポートジェネレーターへのラウンドスコア分析の追加

## ステータス

採用 - 2026-10-31

## 文脈

### 現状

`packages/report-generator/` は `--from` / `--to` で指定した期間のマッチアップ・LP推移・時間帯別勝率（ADR-035）を Markdown で出力し、LLM への分析連携に使っている（ADR-032）。

一方で、レポートは「誰と戦って何勝何敗か」「いつ戦ったか」までは示すが、**試合の中のラウンド構成**は扱っていない。以下は現状では数値で確認できない。

- 1ラウンド目を取った試合と落とした試合で、試合勝率はどれだけ違うか
- 1P / 2P のサイドで成績に差があるか
- 1-1 から 3R に入る試合がどれくらいあり、そこで勝てているか
- 自分の勝ちラウンド・相手の勝ちラウンドの決まり手（通常KO / SA / CA / パーフェクトなど）の内訳

`round_stats.parquet` にはラウンド単位の集計があるが、これは**動画を検出できた試合だけ**が対象で、R2 から別ファイルを取得する必要がある。ラウンドスコアの基本集計は Battlelog の `round_results` だけで全試合に対して行える。

### 要件

1. `battlelog_replays.parquet` だけで集計を完結させる（追加の Parquet 取得を不要にする）
2. 自分の side（1P / 2P）に正規化して集計する
3. `round_results` の値は ADR-037 の規則（`0`=LOSS、`4`=DRAW、それ以外=WIN）で解釈する
4. `round_results` が空・不正・両者でラウンド数が一致しない試合は除外する
5. 既存セクションと独立したセクションとして追加し、`--round-analysis` フラグで有効化する（デフォルトはオフ）
6. 既存の `--from` / `--to` / `--battle-type` / `--player-id` と組み合わせて動作する

### 利用シナリオ

```bash
uv run python -m src.main --from 2026-10-01 --to 2026-11-01 --round-analysis
```

生成されるセクションのイメージ:

```markdown
## ラウンドスコア分析

対象: 1,732試合（round_results が揃っている試合）

### 1ラウンド目の勝敗と試合勝率

| 1R | 試合数 | 勝利 | 勝率 |
|----|--------|------|------|
| 取った | 751 | 545 | 72.6% |
| 落とした | 981 | 204 | 20.8% |

1R を取った試合と落とした試合の勝率差: +51.8pt

### 1P / 2P 別

| サイド | 試合数 | 勝利 | 勝率 | 3R 勝率 (n) |
|--------|--------|------|------|-------------|
| 1P | 636 | 268 | 42.1% | 46.0% (126/274) |
| 2P | 1,096 | 481 | 43.9% | 46.4% (237/511) |

### 1-1 から 3R に入った試合

785試合 / 全1,732試合（フルラウンド率 45.3%）
3R の勝率: 46.2%（363勝 / 785試合）

### 取ったラウンド（自分が決めた）

| 決まり手 | 回数 | 割合 |
|----------|------|------|
| V（通常KO） | 1,413 | 73.6% |
| ... | | |
```

## 選択肢

### 選択肢A: `battlelog_replays.parquet` のみで集計し、`--round-analysis` で有効化

`round_results` の生データから、1R の勝敗・サイド別・3R 勝率・決まり手を集計する。追加のファイル取得は行わない。

**変更ファイル**:
- `src/query.py` — `query_round_score()` と集計用 dataclass を追加
- `src/formatter.py` — `_format_round_score()` を追加
- `src/main.py` — `--round-analysis` 引数追加、`format_report()` への受け渡し

### 選択肢B: `round_stats.parquet` と突合して集計

動画側の検出ラウンド（ゲージ・バーンアウト・被コンボ）と結合し、リソース管理の観点も同時に出す。R2 から `round_stats.parquet` を追加取得する必要があり、動画がある試合だけに絞られる。

### 選択肢C: Web の対戦履歴に常時表示する

`packages/web` の DuckDB-WASM クエリとして実装し、タブまたはセクションで常時見られるようにする。

## 各選択肢の比較表

| 観点 | A: battlelog のみ | B: round_stats と突合 | C: Web に常時表示 |
|------|-------------------|------------------------|-------------------|
| 対象試合数 | ◎ 全試合 | △ 動画がある試合のみ | ◎ 全試合 |
| 追加の取得・実装 | ◎ 不要 | △ R2 からもう1ファイル | △ Web 側に別クエリ |
| ラウンドの解像度 | ○ 勝敗・決まり手 | ◎ ゲージ・バーンアウトも | ○ 同左（A と同じ） |
| LLM 分析との相性 | ◎ Markdown で渡せる | ○ セクションが肥大化 | △ 別途コピーが必要 |
| 実装コスト | ◎ 最小限 | △ | △ |

## 結論

**選択肢A** を採用する。

理由:

- ラウンドスコアの基本指標は Battlelog の `round_results` だけで全試合に対して計算でき、追加の Parquet 取得を必要としない
- 既存の `--hourly-analysis` と同じフラグ方式に揃えられ、CLI の一貫性を保てる
- まず数値を検証し、動画側のゲージ指標と組み合わせたくなった時点で選択肢Bを追加できる（`round_stats` の `matchId` と `replays.replay_id` の対応が必要）

選択肢Bは、動画がある試合だけに絞られ、ADR-067/069 のラウンド数整合フィルタも必要になるため、別 ADR で扱う。選択肢Cは、レポートで数字を検証した後に、同じ集計を Web のタブとして追加する。

## 帰結

### 肯定的影響

- 1R の重み、サイド差、フルラウンド時の勝率、決まり手の傾向を、期間指定で確認できる
- 追加の R2 取得なしで、ローカルの `battlelog_replays.parquet` でも動作する
- `round_results` の解釈（ADR-037）をレポートにも適用し、判定ロジックの一貫性が保たれる

### 否定的影響・制約

- 動画側のゲージ・バーンアウト・被コンボは含まない（`round_stats` を使う別実装が必要）
- `round_results` が欠けた試合、両者でラウンド数が一致しない試合は対象外になる
- 引き分けラウンド（`4`）は勝ちラウンド・負けラウンドのどちらにも数えないため、ラウンド合計が試合数×ラウンド数より少なくなることがある

### 検証

ローカルの `battlelog_replays.parquet`（2026-02〜2026-10、ランクマッチ 1,732 試合）で以下を確認した。

- 1R を取った試合: 751 試合・勝率 72.6% / 落とした試合: 981 試合・勝率 20.8%
- フルラウンド率 45.3%、3R 勝率 46.2%（785 試合）
- 決まり手: 勝ちラウンドは V 73.6% / SA 8.0% / OD 7.5% / P 5.5%、負けラウンドは V 69.5% / OD 10.1% / SA 9.5% / P 6.4%
- 期間外・データなしの場合に「データなし」を出力する
- `--battle-type all` でも動作する

### 将来の見直し条件

- 動画側のラウンド指標（残体力・バーンアウト・被コンボ）と組み合わせた分析が必要になったとき（選択肢B）
- ラウンドスコアを Web で常時見られるようにするとき（選択肢C）
- Battlelog が `round_results` に新しい値（`0` 以外の LOSS など）を追加したとき
